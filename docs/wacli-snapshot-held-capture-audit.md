# Auth, profile and presence effects are scoped; capture is still disabled

The exact-base series now extends **production source and synthetic tests**, not just this audit. WACLI `0008`–`0012` and SDK `0004` add narrow owned-handle effect leases, quoted-message database admission, a raw-handle source inventory and per-callback lineage on top of the reviewed producer series. They are **unsubmitted and unaccepted upstream**. They do not create a usable account restore, enable capture, install code, or authorize source-account access. Mainframe does not apply or run them automatically. **Linux restore and capture remain incomplete.**

## What is now registered and joined

The SDK uses one root-admission mutex for explicit operations, node-loop/handler scopes and key-share roots. `BeginDrain` seals that common gate before waiting on any sub-registry. An accepted scope can register a causal child after sealing; each child has its own token and can register grandchildren after an ancestor finishes. A finished token cannot register work. Registration is before launch, and errors and recovered worker panics are retained.

The source extensions cover the visible socket connection/read/write/disconnect workers, queued-node callbacks and overflow enqueue, reconnect and keepalive callbacks, pairing completion, receipts/acknowledgments, retries, history workers, app-state/key-share/missing-key descendants, protocol notifications, privacy-token workers and event dispatch continuations. Socket connection setup is itself admitted before side effects; failed connection setup releases its scope and lock. A Noise write that outlives its caller's cancellation remains registered until the actual write returns, with its error retained. QR cancellation, emitters and handler cleanup are joined rather than detached.

WACLI adds distinct causal operation tokens and cancellation ownership that survives a command returning while its accepted child still runs. All production bounded-send callers use an owner-aware adapter; the attempt's actual goroutine has a child lease, so its timeout is not its lifetime. Bounded presence attempts use the same pattern. Context-aware application callbacks are admitted before effects and can pass application plus SDK lineage onward. The delegate listener joins accepted handlers, and a media handler now closes and joins its disconnect-reader child before returning. Application close stays unbounded while accepted effects still run; a timeout is not permission to close their stores.

Review hardening removes the send adapter's unscoped compatibility fallback. Missing owners or operation scopes refuse before worker launch; already-canceled attempts finish registration without starting send effects. Synthetic doubles now supply genuine test-only application scopes instead of relying on a production bypass. Regressions verify both refusals and canceled-attempt behavior.

External review also hardens history-consumer startup/rejection and carries accepted lineage through the remaining audited undecryptable-message and offline-preview dispatches. Media panics retain immediate structured/stderr stack diagnostics as well as a drain failure. Successful terminal logout is distinct from unexpected reconnect failure; cancellation of its joined reconnect child is normalized only when that logout requested it.

SDK legacy void producers cannot return every launch rejection to their caller. Rejections are retained as drain failures, not evidence that work was accepted. A regression discards a launch result deliberately and verifies that the callback never executes and the later drain retains both admission and coverage errors. Causal child registration after sealing preserves ownership of accepted work; it is not permission to ignore cancellation or begin arbitrary new effects. Callback cooperation and complete error propagation remain unproven.

The source inventory gates enumerate raw goroutine sites and reject newly unreviewed worker classes. They are review guards, **not proof that arbitrary callback-created work, driver activity, filesystem writers or public handles are owned**. Timer waits inside a registered worker are included in that worker's lifetime; timers and callbacks are also listed by the source inventory for review. No timer count is treated as a capture receipt.

## Narrow handle ownership and callback lifetime

The extension is audited against WACLI `5578d1b6892f50a8f2329b11a6b6e27a1a81f88b` and whatsmeow `v0.0.0-20261017175727-b2b1e71d45e2`, reconstructed by applying the reviewed, digest-pinned preceding patches. `OwnedWA` keeps its underlying client private rather than embedding the broad interface. Each exposed client invocation registers a distinct application child before delegation and finishes that child only when the actual invocation returns. `OwnedDB` similarly protects three selected metadata writes: chat, message and status upserts. File-send uploads, sends, identity lookups and those metadata writes use these facades for the production application. Missing, foreign, canceled or finished application scopes refuse before delegation. Panic causes survive in drain state while the original panic is rethrown; legacy no-error identity readers return zero values and retain admission refusal as a drain error.

Root sealing does not revoke an already accepted live causal parent: it may still register children, and drain must join them. Finishing a parent forbids new children from its token, but a child already admitted before finish retains its own lifetime. Tests borrow live handles before revocation, then verify refused client calls and absent synthetic SQL effects, an invocation that keeps application close blocked after its parent finishes, panic/error retention, and accepted causal metadata writes after root sealing. An explicit raw-DB counterexample still writes after a coverage-refusing drain; it demonstrates the remaining escape, not capture success.

Each SDK event callback now gets a separate child scope, finished on its own return, error or panic. A context retained by an earlier callback cannot register children while a later callback is still running. `BeginOperation`, worker launch, `BeginScope` and `BeginLifecycleScope` reject expired or foreign lineage rather than silently opening an unrelated root. A new scope with no lineage remains a normal root until sealing. Deliberately discarding context or starting an arbitrary goroutine is still outside this additive contract; no callback-completeness claim is made.

## Quoted-message reads and the remaining raw calls

WACLI `0009` routes file-send quoted-message and media-metadata reads through `OwnedDB.GetMessage` and `GetMediaDownloadInfo`. Each read admits a child before querying and finishes it only when the underlying synchronous call returns or panics. File and sticker sends select both owned facets before using raw accessors; partial owned/raw adapters refuse rather than silently mixing ownership contracts. Sticker client and metadata effects now use the same narrow owned facades. Callers exposing neither facet retain a legacy compatibility path and are not certified by this change. Text-send reply lookup still uses a raw adapter.

Synthetic query counters assert zero database invocations and zero client effects for finished, missing, foreign, canceled and sealed-without-live-parent contexts. A live accepted parent can still start a read after root sealing; blocked message and media reads keep drain waiting after that parent finishes, and retain their actual returned error. Panic causes remain drain failures. Command-route regressions panic if refusal touches a raw accessor or attempts a client invocation; partial-facet regressions cover both file and sticker entry points.

The [complete final-chain inventory](wacli-raw-handle-inventory.md) enumerates **164 remaining syntactic production accessor calls: 80 `DB()` and 84 `WA()`**, all conservatively marked **UNPROVEN**. Its AST fixture includes path, enclosing function, source expression, location and occurrence identity. A normal test fails on additions, deletions or drift. This is a review gate, not receiver/type resolution or proof of joined ownership. Method values, aliases, direct fields/store APIs, arbitrary descendants and public synchronous SDK methods remain separate gaps. No SDK public synchronous method migration is claimed by `0009`.

Migrated routes are message list/search/starred/show/context/export reads and changes; call listing; history coverage/fill planning; and store statistics. Command helpers receive facades or values, never raw database/client handles. Each effect registers a child before database/resolver work and releases it only on actual return or panic. Missing session files do not trigger resolver construction. A route AST guard also rejects raw method values.

Accepted live parents can still create causal children after root sealing. This removes 18 DB accessor calls, not 18 whole-client coverage gaps. ## Contact effects and account-save cleanup

WACLI `0011` scopes contact search/show, refresh, alias/tag metadata, system import/clear, live registration checks and account saves. Delegated checks/saves select the same narrow facades. Every actual DB, resolver and client invocation has a child lease. Resolver access stays private and preserves the original eager session errors and read-only identity view even for writable metadata commands; a missing session does not create a client or session file. The save wrapper joins the complete unchanged account-save persistence/journal path. ## Authentication, profile and presence effect completion

WACLI `0012` adds a private application authentication facade for login/bootstrap sync, writable status, authenticated connection and logout. The lease spans the complete underlying operation, including its private migration/database work and existing registered callbacks/workers. Profile mutations/reads and presence sends/subscriptions select narrow owned client methods, and watched presence holds a lease through subscription, handler removal and wait completion. Delegated presence selects the same facades; other delegated command families are not reclassified. A timeout ends the caller's wait, not an accepted bounded attempt's lifetime. Presence reconnect leases disconnect and authenticated connection. Offline-presence cleanup strips cancellation while preserving a still-live parent token, runs before parent finish, and retains errors; it does not manufacture a fresh root after sealing.

Selected command teardown finishes the parent token before `CloseWithError` joins remaining accepted descendants; otherwise close would wait for its own command. Work, cleanup, close and lock-release failures are propagated rather than discarded. Counted synthetic clients verify zero effects on refused scopes, actual channel-blocked status/connect/sync/logout/profile/subscription joining, timeout/cancellation survival, panic/failure retention, and live-lineage cancellation-stripped cleanup. The independent read-only auth-status SQL reader remains synchronous and unchanged, outside the application facade certificate. Application initialization, profile-input filesystem reads, public SDK/direct store APIs and arbitrary unregistered descendants are not certified as a whole-program boundary.

The reviewed AST regeneration removes exactly 14 WA calls (3 auth, 7 profile, 3 presence, 1 delegated presence), leaving **164 calls: 80 DB / 84 WA**, all UNPROVEN. Seven unchanged residual `send_ipc.go` sites move only in location. No other path was filtered, reclassified or updated.

## Why no held capture can be returned

Both production `BeginDrain` APIs still return a nil held boundary and an explicit coverage error, even after all registered work has finished. The SDK's `LifecycleCoverageGaps()` returns a fresh, fixed gap list; a caller cannot approve, remove or override it. Known operational errors remain distinguishable from coverage refusal. Ordinary error-free close means only that the known joined operations did not fail.

Failure retention is deliberately conservative: a later successful retry does not prove an earlier attempt had no partial persistence effects, so it does not clear that attempt's drain failure. A regression preserves this distinction between command success and lifecycle evidence. Each registry retains its first operational cause, not an exhaustive error history; later failures can be masked diagnostically, but cannot turn a failed drain into success. Broader bounded multi-cause diagnostics remain follow-up work, not a capture prerequisite satisfied by this series.

Remaining gaps are concrete:

- Public synchronous SDK methods, `Store`, `DangerousInternals`, legacy application `DB()`/`WA()` and previously borrowed raw handles are not a revocable admission facade. The new facades are intentionally narrow, not replacements for every existing method. File/sticker quote lookups are migrated for production `App`, but text-send replies, legacy compatibility adapters, other commands and direct application-store uses have not all migrated. The 164-call inventory records those remaining accessor sites without certifying them. A source audit cannot fence every direct synchronous call.
- Legacy/void handlers and arbitrary user callbacks can start unregistered work or discard lineage. The additive context API helps cooperative code; it cannot force an external callback to use it. Some existing callback continuations still capture their outer context, and void callbacks cannot return all persistence errors.
- Standalone socket callers can omit the additive hooks. Foreign HTTP transports, SQL drivers, already-open writable descriptors, shared stores and independent processes remain outside the client owner.
- Queued frame/node membership and every previously log-only persistence continuation have not been verified as a whole-client logical frontier. A narrow join is not an exhaustive cross-database transaction boundary.
- Media still needs an immutable retained membership set tied to that complete producer frontier, plus restored-reference mapping and platform-enforced ownership or isolation.

These are implementable missing guarantees, not a claim of technical impossibility. If any class cannot be comprehensively registered, its gap stays explicit. No force flag, caller-supplied receipt, approval label or root allowlist turns this series into capture authority. Snapshot create remains denied before source discovery or I/O; unsupported roots cannot be silently omitted from a successful archive because no archive can be published.

## Immutable media remains a separate diagnostic

The existing Linux media code enumerates the pinned schema's nonempty `messages.local_path` and `message_local_media_aliases.local_path` references, retaining duplicate and orphan references. It stages separate content objects in kernel-sealed `memfd` files and hashes their actual bytes after write/grow/shrink/seal locks are installed. Originals are not modified or deleted. Known lengths are checked; zero/NULL lengths remain unspecified.

Missing objects or fingerprints, malformed/orphan metadata, changed bytes, unsupported platforms/kernels, cancellation, special files or resource limits fail the entire set. Limits remain 1,024 references/descriptors and 256 MiB of staged bytes; there is no successful truncated set. A pre-existing writable descriptor cannot change a successfully verified sealed object's recorded bytes, but this does not own the original namespace or database membership.

`store verify-media` still reports only `verified-byte-objects-only`, `boundary: UNVERIFIED`, `complete: false`, `capture_enabled: false` and `publishable: false`, then closes its descriptors. It is not an archive, relocation or activation operation. A store lock excludes cooperating writers of that store only; a stable hash, mode 0700, a symlink-free path or a read-only bind view does not exclude independent writers or retained writable handles.
