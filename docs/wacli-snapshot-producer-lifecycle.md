# WACLI capture still needs a producer-wide boundary

**Capture remains disabled. Fully usable Linux restoration is not implemented.** The investigation found two dependency-level shutdown counterexamples in addition to the accepted-delegate gap from PR #34. Joining delegate handlers alone would not fix capture. This change adds diagnostics, preservation tests and documentation only; it changes no runtime capture, backup or restore code.

The [shutdown-only follow-up](wacli-snapshot-shutdown-boundary.md) adds real-SQL close/error counterexamples and a real offline CLI media writer under a held store lock. Neither successful database close nor daemon shutdown supplies the missing completed-work and media-ownership boundary.

## The new reproducible failures

The [dependency diagnostic patch](../patches/wacli/0003-synthetic-dependency-boundary-probes.patch) runs the real pinned whatsmeow producer paths with in-memory fake stores. It opens no database or socket and uses no account, credentials, chats or personal media. Its deprecated `DangerousInternals` calls are test injection points, not a proposed production API.

1. **A closed node queue does not mean its current handler finished.** A synthetic chat-state node enters a channel-blocked event handler. Canceling the connection context closes the real queue's completion signal before that handler is released. The counterexample needs no five-second disconnect timeout: the queue itself exits while the child node goroutine remains alive. See [dependency `client.go:908–971`](https://github.com/tulir/whatsmeow/blob/b2b1e71d45e2/client.go#L908-L971).
2. **A key-share worker can outlive wrapper close and reach both persistence domains.** The real protocol handler starts a key-share worker using `context.WithoutCancel`. The fixture blocks its key-store call, then observes WACLI's actual `wa.Client.Close()` return before releasing it. Once released, the worker completes the fake session-store write and the real WACLI key guard calls the fake app-metadata store. These are in-memory observations of write entry points, not SQL commits. Already-synced fake app-state versions prevent subsequent network fetches. See [dependency `message.go:923–925`](https://github.com/tulir/whatsmeow/blob/b2b1e71d45e2/message.go#L923-L925), [key storage and continuations at `message.go:827–865`](https://github.com/tulir/whatsmeow/blob/b2b1e71d45e2/message.go#L827-L865), [WACLI guard `app_state_keys.go:40–70`](https://github.com/openclaw/wacli/blob/5578d1b6892f50a8f2329b11a6b6e27a1a81f88b/internal/wa/app_state_keys.go#L40-L70), and [wrapper close `client.go:64–75`](https://github.com/openclaw/wacli/blob/5578d1b6892f50a8f2329b11a6b6e27a1a81f88b/internal/wa/client.go#L64-L75).

The wrapper fixture intentionally has no SQL container. It proves missing producer joining, not that writes succeed against an already-closed real database. Closing SQL first can turn pending accepted work into failed/lost writes; that is not a successful application drain either. The queue fixture calls the real queue loop directly; it is not a connected-websocket integration test.

These counterexample tests should pass while the pinned behavior remains unsafe. If a future dependency changes the behavior, investigate the failing counterexample and replace it with a positive drain contract test; do not weaken it to continue claiming this gap exists.

## Media references are not the file set

A complete capture must distinguish these states without erasing the original references:

- **Remote-only:** media metadata exists but no local path. This does not prove the server/phone can still supply bytes. An offline restore cannot promise all such media is downloadable.
- **Missing or invalid local:** a recorded path exists in the database but the file is missing or fails expected size/hash verification. Do not relabel it as successfully captured or silently clear it.
- **Local present, internal or external:** capture the verified bytes under an approved root and preserve a relocation mapping. A store-tree copy misses caller-selected external output.
- **Aliases:** enumerate both the current local path and retained local-path aliases; a single `messages.local_path` scan is not complete.
- **Output-only:** explicit read-only output may create a file without updating the database. It is not discoverable from DB references; decide whether approved output roots include it, rather than assuming all arbitrary outputs are account members.

See [output path selection](https://github.com/openclaw/wacli/blob/5578d1b6892f50a8f2329b11a6b6e27a1a81f88b/internal/app/media.go#L113-L139), [read-only explicit output](https://github.com/openclaw/wacli/blob/5578d1b6892f50a8f2329b11a6b6e27a1a81f88b/cmd/wacli/media_download.go#L37-L79), [current and alias paths](https://github.com/openclaw/wacli/blob/5578d1b6892f50a8f2329b11a6b6e27a1a81f88b/internal/store/messages.go#L260-L280), and [media file publication](https://github.com/openclaw/wacli/blob/5578d1b6892f50a8f2329b11a6b6e27a1a81f88b/internal/wa/media.go#L63-L137).

The [Mainframe synthetic membership regression](../tests/test_wacli_snapshot_boundary.py) preserves generic remote-only, missing, external and alias reference rows while leaving external/output-only bytes outside the supplied stage. This is deliberately not a WACLI schema parser, discovery test, migration or semantic restore. It protects the distinction between preserving a supplied database and resolving its media membership.

## The exact boundary that is still unsolved

Before enabling capture, one reviewed owner must **close admission before draining**, including CLI/delegate requests, all callbacks and their descendants, every dependency persistence path, and all approved media mutations. Accepted operations need a defined completed application frontier; cancellation, store-close errors, or rejecting the second half of an already accepted cross-store operation cannot count as success. The gate must stay held across membership enumeration, both database captures, file capture and validation, with no reopen until release. Aborts/timeouts must never publish.

A WACLI-only WaitGroup around delegates is insufficient. Wrapping just the SQL store is also insufficient: it can allow part of a logical operation, reject its later continuation, or miss in-memory state and filesystem work. A real implementation needs a dependency-supported exhaustive producer lifecycle (or a reviewed, explicitly maintained dependency change) plus an enforceable filesystem ownership/isolation model for approved roots. No such contract was found in the pinned code. No dependency fork or version change is made here.

Process exit eliminates that process's future writes but does not, by itself, prove accepted work drained. Suspending a process or taking a filesystem snapshot gives at most the corresponding crash boundary; it does not establish the required application frontier. Neither excludes a separate writer to an external media path. Broadly denying writes or killing producers is not a substitute for a lossless drain.

After a valid source boundary, Linux still needs version/schema acceptance, account/config mapping, alias/external-media relocation, non-overwriting activation, local message/search/media checks and linked-device usability validation. A byte-preserving backup cannot prevent server-side credential revocation. The goal of 100% usable Linux restoration therefore remains unmet; it has not been redefined as valid SQLite files or successful encryption.

**Windows was not run.** The offline Windows machine was not accessed. Linux synthetic fixtures, race detection and any Windows cross-compilation in the standard contribution gate do not validate Windows-origin capture or restoration. Mainframe and the proposed producer still refuse capture before source I/O; no receipt, lock, quiescence or force override is introduced.
